# Практическая работа 2. Вариант 10, ИКБО-13-25

Инструмент визуализации зависимостей Java Maven на C++17 для Windows.
Программа читает JSON-настройки, получает POM из репозитория, строит граф
нерекурсивным DFS и показывает изображение D2. Реализованы все пять этапов.

## Сборка и запуск

Нужен MinGW-w64 с g++ в PATH. Сборка проверена на g++ 13.2.0.
Для изображений нужен D2; проверена версия 0.9.0.
D2 ищется в `%LOCALAPPDATA%\Programs\D2\d2.exe`, затем в PATH.
Можно указать другой путь переменной `D2_EXE`.
На компьютере, где выполнена работа, D2 уже размещён во втором каталоге.

Откройте PowerShell в папке проекта:

```powershell
.\run.bat build
.\run.bat test
.\run.bat
```

Сборка находится в `build\app.exe`. Для запуска готовой сборки:

```powershell
.\build\app.exe --stage 3
```

`run.bat` переходит в каталог проекта и собирает программу.
Для этой установки MinGW он явно выбирает согласованные заголовки компилятора.
C++ runtime связывается статически; библиотеки WinHTTP, XmlLite и Shell входят в Windows.
Программа не использует Maven или сторонние библиотеки для получения зависимостей.
WinHTTP загружает XML, XmlLite разбирает XML, а зависимости извлекает наш код.
D2 получает уже построенный граф и только рисует его.

Обычный запуск создаёт `.d2` и `.svg` в `output` и открывает картинку.
`--no-open` сохраняет изображение, не открывая его.
Если D2 отсутствует, текст диаграммы сохраняется, а программа сообщает об ошибке.
Инструкция установки: [официальная документация D2](https://d2lang.com/tour/install/).

## JSON-конфигурация

По умолчанию используется `config.json`. Другой файл передаётся первым аргументом.
Все пять полей обязательны; неизвестные поля считаются ошибкой.

```json
{
  "package": "A",
  "repository": "examples/repository.json",
  "test_mode": true,
  "max_depth": 4,
  "filter": ""
}
```

| Поле | Назначение |
| --- | --- |
| `package` | В тестах имя из A-Z; для Maven точные координаты `group:artifact:version` |
| `repository` | Путь к тестовому JSON относительно конфигурации либо HTTP(S) URL Maven-репозитория |
| `test_mode` | `true` для файла графа, `false` для Maven |
| `max_depth` | Целое число от 0 до 2147483647; глубина корня равна 0 |
| `filter` | Исключаемая подстрока; пустая строка отключает фильтрацию |

Фильтр чувствителен к регистру и проверяет полные координаты пакета.
Исключённый узел не включается в граф, обход через него прекращается.
Если исключён корень, получается пустой граф.
При достижении предельной глубины узел показывается, его зависимости не запрашиваются.

Тестовый репозиторий — JSON-объект со списками прямых зависимостей:

```json
{"A": ["B"], "B": []}
```

Все имена состоят из заглавных латинских букв. Каждый узел должен иметь собственный ключ.
Повторные рёбра объединяются; циклы и петли допустимы.

## Этап 1. Настройки и ошибки

```powershell
.\run.bat --stage 1
```

Выводятся все пять параметров в формате `ключ = значение`.
Для пути к тестовому файлу выводится путь, разрешённый относительно конфигурации.
Ошибка сопровождается сообщением `Error: ...` и кодом завершения 1.
Успешный запуск возвращает 0.

`run.bat test` демонстрирует обработку ошибок всех параметров:

| Ошибка | Проверка |
| --- | --- |
| Неверное имя `package` | Строчная буква в тестовом режиме, неверные координаты Maven |
| Неверный `repository` | Нет файла, URL с неподдерживаемой схемой |
| Неверный `test_mode` | Строка вместо логического значения |
| Неверная `max_depth` | Отрицательное число, дробь, переполнение |
| Неверный `filter` | Число вместо строки |
| Общая ошибка конфигурации | Нет поля, неверный тип любого поля, неизвестное поле, повреждённый JSON |

Также обрабатываются ошибки сети, HTTP-статус, некорректный XML, неизвестные свойства POM,
отсутствующий пакет тестового репозитория и неверные аргументы командной строки.

## Этап 2. Прямые зависимости Maven

```powershell
.\run.bat examples/junit.json --stage 2
```

Результат:

```text
junit:junit:4.13.2
  -> org.hamcrest:hamcrest-core:1.3
```

Адрес POM составляется из группы, имени и версии; точки группы заменяются на `/`.
Учитываются родительские POM, свойства `${...}`, наследуемые зависимости и `dependencyManagement`.
Обычный JAR и тестовый JAR различаются по типу и classifier.
POM кэшируются в памяти на время запуска. Показываются compile/runtime зависимости.
Test, provided, system и optional пропускаются.

## Этап 3. DFS, глубина, фильтр, циклы

```powershell
.\run.bat --stage 3
.\run.bat examples/cycle-config.json --stage 3
.\run.bat examples/depth.json --stage 3
.\run.bat examples/filter.json --stage 3
.\run.bat examples/leaf.json --stage 3
```

В основном примере A зависит от B и C, они — от D, D — от E; F зависит от A.
Циклический пример: A → B → C → A, отдельно находится D.
Пример глубины оставляет A, B, C. Фильтр исключает B, сохраняя ветку через C.
Пример листа оставляет только E.

DFS использует вектор как стек: `push_back` добавляет вершину, `pop_back` извлекает последнюю.
Рекурсивных вызовов при обходе нет. Словарь минимальных глубин останавливает циклы.
Если обнаружен более короткий путь, узел раскрывается повторно, чтобы не потерять потомков.

## Этап 4. Обратные зависимости

```powershell
.\run.bat --stage 4 --reverse D
.\run.bat --stage 4 --reverse A
.\run.bat examples/cycle-config.json --stage 4 --reverse B
.\run.bat examples/leaf.json --stage 4 --reverse F
```

Рёбра разворачиваются, затем применяется тот же нерекурсивный DFS, глубина и фильтр.
Стрелка на этом этапе идёт от искомого пакета к использующему его пакету.
Для D находятся B, C, A и F. Для F обратных зависимостей нет.
Без `--reverse` целью является `package`. Флаг `--reverse` разрешён только на этапе 4.

Тестовый режим ищет во всём файле, включая несвязные компоненты.
В режиме Maven поиск ограничен графом, полученным от настроенного корня с заданными глубиной и фильтром.
Поиска всех пользователей пакета во всём Maven Central нет.

## Этап 5. Визуализация трёх пакетов

```powershell
.\run.bat examples/junit.json
.\run.bat examples/slf4j.json
.\run.bat examples/httpclient.json
```

Этап 5 используется по умолчанию. Можно указать `--stage 5` явно.
Для сохранения без открытия добавьте `--no-open`.
Узлы D2 имеют идентификаторы n0, n1 и так далее, координаты Maven используются как подписи.
Текст и SVG получают имя анализируемого пакета с заменой двоеточий на подчёркивания.

### Сравнение с Maven

Проверено 20.11.2026: Maven 3.9.11, Maven Dependency Plugin 3.8.1, область runtime.
Репозиторий — `https://repo.maven.apache.org/maven2`, глубина 4, фильтр выключен.
Для каждого пакета создан временный POM с единственной зависимостью на этот пакет.
Искусственный корень `student:comparison:1` исключён из сравнения.
Сравнивались наборы вершин и направленных рёбер. Во всех трёх случаях они совпали.

| Пакет | Вершины | Рёбра | Результат |
| --- | --- | --- | --- |
| `junit:junit:4.13.2` | 2 | 1 | Совпадает |
| `org.slf4j:slf4j-simple:1.7.36` | 2 | 1 | Совпадает |
| `org.apache.httpcomponents:httpclient:4.5.14` | 4 | 3 | Совпадает |

Вывод штатного `dependency:tree` без искусственного корня:

```text
junit:junit:jar:4.13.2:compile
\- org.hamcrest:hamcrest-core:jar:1.3:compile

org.slf4j:slf4j-simple:jar:1.7.36:compile
\- org.slf4j:slf4j-api:jar:1.7.36:compile

org.apache.httpcomponents:httpclient:jar:4.5.14:compile
+- org.apache.httpcomponents:httpcore:jar:4.4.16:compile
+- commons-logging:commons-logging:jar:1.2:compile
\- commons-codec:commons-codec:jar:1.11:compile
```

Maven показывает дерево с типами и областями, наша программа — граф D2 с координатами.
Различия в порядке вывода и расположении узлов не изменяют состав зависимостей.
На сложных пакетах возможны расхождения: учебная программа не реализует активацию профилей,
импорт BOM, exclusions, разрешение конфликтов версий, диапазоны версий и поиск SNAPSHOT по метаданным.
BOM, classifier и тип не-JAR для включаемой зависимости вызывают явную ошибку.

Для повторения сравнения установите Maven и Java. Следующий PowerShell-код использует временный каталог:

```powershell
$dir = Join-Path $env:TEMP 'practice2-comparison'
New-Item -ItemType Directory -Path $dir -Force | Out-Null
foreach ($name in 'junit', 'slf4j', 'httpclient') {
    $config = Get-Content "examples/$name.json" -Raw | ConvertFrom-Json
    $g, $a, $v = $config.package.Split(':')
    $pom = "<project><modelVersion>4.0.0</modelVersion>"
    $pom += "<groupId>student</groupId><artifactId>comparison</artifactId><version>1</version>"
    $pom += "<dependencies><dependency><groupId>$g</groupId><artifactId>$a</artifactId>"
    $pom += "<version>$v</version></dependency></dependencies></project>"
    $pom | Set-Content "$dir/pom.xml" -Encoding UTF8
    .\build\app.exe "examples/$name.json" --stage 3
    mvn -B -ntp -f "$dir/pom.xml" org.apache.maven.plugins:maven-dependency-plugin:3.8.1:tree -Dscope=runtime
}
```

Если старая Java не доверяет сертификату репозитория, в Windows можно использовать системное хранилище:

```powershell
$env:MAVEN_OPTS = '-Djavax.net.ssl.trustStoreType=Windows-ROOT -Djavax.net.ssl.trustStore=NONE'
```

Проверка сертификатов при этом остаётся включённой. Для работы нашей программы Java и Maven не нужны.

## Функции и файлы

| Файл | Функции |
| --- | --- |
| `src/app.h` | Структуры Json, Config, Dependency, Pom; типы Graph, Loader, Fetcher; объявления функций |
| `src/json.cpp` | `read_file` читает файл; `parse_json` и JsonParser разбирают JSON, строки, Unicode и числа |
| `src/config.cpp` | `valid_package` проверяет имя, `load_config` читает настройки, `print_config` выводит их |
| `src/http.cpp` | `wide` и `utf8` преобразуют кодировки; `http_get` выполняет GET с проверкой статуса и тайм-аутами |
| `src/xml.cpp` | `parse_pom` получает родителя, свойства и зависимости; xml_nodes, child, text разбирают структуру |
| `src/maven.cpp` | `pom_url` строит URL, `expand` раскрывает свойства, aliases добавляет свойства проекта |
| `MavenRepository` | Конструктор задаёт репозиторий и загрузчик; `direct` получает прямые зависимости и кэширует POM |
| `src/graph.cpp` | `load_test_repository`, `build_graph`, `print_graph`, `reverse_graph` |
| `src/diagram.cpp` | `d2_text` создаёт D2; `save_diagram` сохраняет, вызывает render и открывает SVG |
| `src/main.cpp` | options проверяет аргументы, run выбирает этап, wmain обрабатывает ошибки и Unicode-пути |
| `tests/tests.cpp` | Проверки JSON, настроек, Maven, DFS, обратного поиска и диаграмм без доступа к сети |
| `examples/` | Два тестовых репозитория, примеры циклов, глубины, фильтра, листа и трёх пакетов Maven |

В JSON-парсере отдельные методы читают пробелы, символы, строки, Unicode, коллекции и значения.
В XML-парсере dependencies извлекает описания зависимостей только из нужного раздела POM.
В визуализации label экранирует подпись, quote экранирует аргумент Windows, render запускает D2.
InternetHandle закрывает HTTP-дескрипторы. В тестах check проверяет результат, fails ожидает ошибку;
остальные функции группируют проверки по модулям.
